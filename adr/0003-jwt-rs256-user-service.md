# 0003. JWT подписывает user-service (RS256)

- **Статус:** принято
- **Дата:** 2026-10-01

## Контекст

Несколько сервисов должны знать, кто отправил запрос. Проверять каждый запрос обращением к user-service — лишняя задержка и зависимость. Симметричная подпись (HS256) требует раздать общий секрет всем сервисам: утечка из любого из них позволяет подделывать токены.

## Решение

Токены JWT выпускает только user-service и подписывает закрытым ключом по алгоритму RS256. Открытый ключ публикуется по адресу `/.well-known/jwks.json`. Остальные сервисы проверяют подпись локально открытым ключом.

## Последствия

- Проверка токена не требует сетевого запроса.
- Закрытый ключ хранится только у user-service, вне репозитория.
- Отозвать выданный токен до истечения срока нельзя: срок жизни токенов должен быть разумно коротким, а для зарегистрированных игроков позже понадобится refresh-токен.
- Смена ключа (ротация) поддерживается через `kid` в JWKS.
